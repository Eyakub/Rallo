B · Hidden recommended

Clean like Apple Notes and Notion. Markers show only on the caret’s line (here, the first). The cost: a line re-wraps when the caret enters or leaves it, so text can shift a little under a click. It’s the hardest part to build, so it ships after ⌘B and styling, which work the same in A and B.

7 · Decided in the plan, and open

My calls check these

  • The note stays Markdown in items.text. No schema change, no FFI type change, no export format bump. Storing rich text separately would split the truth between the app and the CLI.
  • A small Rust parser for exactly the marks above, next to tags.rs, reached over the FFI like tag_ranges. Full CommonMark would turn old notes with a --- under a line, or four-space indents, into headings and code.
  • Shortcuts copied from Apple Notes. Strikethrough ⇧⌘X and Code ⌘E come from Slack and Notion, since Notes has none. The panel’s own ⌘E (edit a row) keeps working there.
  • Search keeps matching the stored text. A phrase that crosses a marker (“rich text in” across **) won’t match; single words do.
  • The first line stays the note’s title, as today, so there is no Title style: Heading is #, Subheading is ##.
  • No Dashed List; one bullet style.

Open for you your call

  1. Markers: B · Hidden (recommended) or A · Dimmed.
  2. Underline ⌘U and highlight ⇧⌘E aren’t Markdown. Skip both (recommended), or store them as <u>…</u> and ==…==.
  3. Paste: keep pasting plain text (recommended for now), or turn bold, links and lists copied from Notes or a web page into Markdown.
  4. Selection bar (section 5): leave it out (recommended) or add it.
