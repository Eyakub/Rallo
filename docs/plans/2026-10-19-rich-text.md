# Rich Text in Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Markdown-backed rich text in the Notes window editor: styled as you type, marks hidden off the caret's line, Apple Notes shortcuts (⌘B and the rest) in a new Format menu and an Aa toolbar popover.

**Architecture:** The note stays plain Markdown in `items.text`. A small Rust parser (`items/markdown.rs`) returns UTF-16 spans and plain text over the FFI, like `tag_ranges`. Swift styles the `NSTextView` by attributes only (hiding = 0.01 pt clear font), draws bullets/checkboxes/quote bars/code boxes in an `NSLayoutManager` subclass, and edits the string through pure `NoteFormatting` functions applied with `shouldChangeText`/`didChangeText` (undo, autosave).

**Tech Stack:** Rust (rallo-core, UniFFI in rallo-ffi), Swift 5 / AppKit TextKit 1 / SwiftUI, macOS 14+.

**Spec:** `docs/decisions/0023-rich-text-notes.md` (read it first; its grammar table and shortcut table are normative). Mockup: `docs/mockups/rich-text.html`.

  pub enum Kind { Marker, Bold, Italic, Strike, Code, LinkText, LinkUrl, Heading(u8), Bullet, Number,
                  TaskBox { checked: bool }, TaskDone, ListContent, Quote, CodeBlock, CodeFence, Divider }
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]

- Produces (FFI → Swift): `MarkdownKind` (`uniffi::Enum`, same cases; `Heading { level: u8 }`, `TaskBox { checked: bool }`), `MarkdownSpan { kind, utf16_start: u32, utf16_len: u32 }` (`uniffi::Record`), `#[uniffi::export] fn markdown_spans(text: String) -> Vec<MarkdownSpan>`, `#[uniffi::export] fn plain_text(text: String) -> String`. Swift sees `markdownSpans(text:)`, `plainText(text:)`, `MarkdownKind.heading(level:)`, `.taskBox(checked:)`, `span.utf16Start`, `span.utf16Len`.

Span semantics (ranges exclude the line terminator; `\r\n` and `\n` both end a line):
- `Heading(n)`: the whole line; `Marker`: the `#`s plus following spaces. Needs 1–6 `#`, then at least one space (`#` alone, `#tag` are not headings). Up to 3 leading spaces.
- Bulleted item: `Bullet` = the `-`/`*`/`+` char; `ListContent` = after the marker's spaces to line end.
- Task item (bullet then `[ ]`/`[x]`/`[X]`, then a space or line end): `Marker` = bullet + its spaces; `TaskBox{checked}` = the 3-char box; `ListContent` (and `TaskDone` when checked) = after the box's space.
- Numbered item (1–9 digits, `.` or `)`, space): `Number` = digits + delimiter; `ListContent` as above.
- `Quote`: the whole line; `Marker`: `>` plus one optional space. The rest is parsed inline.
- Code block: `CodeBlock` from the opening fence's line start to the closing fence's line end (or the text end); `CodeFence` = each fence line. No inline parsing inside.
- `Divider`: the whole line, 3+ of the same `-`, `*` or `_` and optional trailing spaces, nothing else.
- Inline (paragraphs, headings, quotes, list content): `Marker` per delimiter; `Bold`/`Italic`/`Strike`/`Code` = content between delimiters; link = `Marker` `[`, `LinkText`, `Marker` over `](url)`, `LinkUrl` over url; escape = `Marker` over `\`. Rules from 0023 §2: code spans and links first (masked), then `**`, `~~`, then `*`/`_` italic; opener followed by non-space, closer preceded by non-space, content non-empty, same line; `_` needs no alphanumeric outside; `__`/`***` are literal.
- `plain_text` removes: `Marker` ranges, each `CodeFence` line with its line terminator, `Bullet` plus following spaces, `TaskBox` plus one following space, a `Divider` line's text (line kept, empty). Keeps `Number`, `#tags`, line breaks.

      static func newline(text: String, selection: NSRange, marks: [MarkdownSpan]) -> FormatEdit?  // nil: plain newline
